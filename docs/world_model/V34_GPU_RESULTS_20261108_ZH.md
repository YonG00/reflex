# V34 GPU结果：事件写回收益小，融合误差定位到Physical WM

## 结论

本轮没有达到完整WM＋Actor低于1秒，也没有启动正式训练。事件写回候选严格数值通过，但Actor＋Critic中位耗时仅下降约1.85%，暂不提升为正式训练配置。最小Actor＋WM的单步融合很快，但状态与实际Adam更新仍不满足默认dtype容差，不作为可用加速成绩。

主要新增证据：WM分段编译与Actor＋WM单步融合，在相同输入的第6步均首先于同一箱子角速度分量超差。该最小链不包含原生事件/FK/任务奖励，因此不能把融合数值失败归因于事件处理本身。下一步首先细分Physical WM的features/canonical、normalization、MLP、integrate边界，而非继续盲目扩大图。

完整原生和配对测试源码5c54efb；仅修正诊断输入梯度元数据后的最小链R2为c0123d5。共同checkpoint为V29从零预热500轮＋联合30分钟最终存档，AMP计数919正常恢复。服务器独立worktree `/root/reflex-v33-study`，未修改原训练仓库或覆盖旧输出。

## 探针修正与不适用证据

首次新probe对递推输入统一detach，改变实际H32从第2步起的requires_grad元数据。该版本single_step在第2步出现约0.879状态差、0.242动作差；它不是正常H32的有效数值证据。独立GPU复核显示原版与deepcopy eager输出严格相同；保留requires_grad后上述异常消失，回到1e-5量级差异。没有据此断言PyTorch底层错误或训练Actor发生0.24级误差。

修正c0123d5保留输入梯度元数据但截断诊断自身的跨步图，新增回归测试；22项CPU专项通过（11.20秒）。R2重跑三组成功完成，以`fusion_boundary_probe_r2.json`为准；初版保留作审计，不覆盖。两次最小CLI退出0仅代表程序完成，整体numeric_passed仍false。
