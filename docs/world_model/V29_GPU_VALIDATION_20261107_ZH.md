## 七、Actor CUDA Graph与后续决策

当前已验证的是分段torch.compile/融合和局部批处理，**没有Actor CUDA Graph replay的profiler验收证据**。原生事件存在动态索引、分支、随机计时与状态写入，H32反传还要求保留每步输出生命周期，不能直接把整个H32作为静态图捕获。

后续如继续优化，应对静态单步WM/FK/解析计算段单独验证Graph capture/replay，检查cudaGraphLaunch与kernel数量，以及状态/事件/梯度/Adam更新，保留原生事件。此前冷编译成本已经较高，不将“开启选项”当成实际收益。

当前建议：512为已验收容量候选；解析终止、305 Critic和批处理基础正确性通过，可用于下一轮受控训练。精简WM需完成更充分的从零学习与接触预测检查；本轮不宣称站立或接箱效果改善，不启动半小时训练。
