| 指标 | reference | fused |

| FK前向调用 | 34 | 34 |
| Actor+Physical WM core调用 | 不适用（分段） | 32 |

launch只减少约1.45%，事件和奖励反向工作几乎原封不动。34次FK与初始、32步以及一次额外状态写入相容，没有“每步重复很多次全身FK”的计数证据。不能仅为重复FK再造优化。

在Profiler中事件前向分组CPU self累计约636/641ms，对应事件反向约312/305ms，奖励反向约271/272ms；这些是跨操作归因统计，不是独占关键路径wall-clock，不能直接相加预言可节省多少。Actor MLP参数数量不是这批碎片化操作的解释。

Trace内完整更新span为2.897/2.797s；BPTT标注span为1.285/1.226s。更新开始到BPTT开始为1.525/1.484s，包含采样和前向等工作，不命名为纯Actor前向。Profiler增加开销，不能把这些数值当作未打点稳态分项。

捕获到的CUDA活动时间并集约256/254ms，活动条目91,436/90,091（包含传输，不等于纯kernel数）。这与大量短GPU操作和主机调度间隙一致，但不是SM利用率、不是精确可节省时间；缺口还需与Chrome运行时事件、捕获覆盖对照。无法匹配的反向活动保留unmatched/shared，融合后归因边界改变，不能对比单个分组的差额冒充净收益。
