# V30 GPU 实测与合并结论

## 结论

已验证的 Actor 执行优化组合，在同组固定条件下由 **2.5077 秒降到 1.8709 秒，耗时降低25.4%**。另一组同配置参考测到1.7259秒，说明短测存在运行波动，不拿跨组最小值计算收益。

**整轮 WM＋Actor/Critic 低于1秒的目标未达成。没有启动正式训练，没有新的站立或接箱成功率结果。** 各分项来自独立配对实验，不能把最优耗时之和称为完整一轮实测；当前未做新组合的持续端到端联跑。

主线提供 `configs/world_model/joint_execution_v30_verified_actor_trial.json`：只启用通过验证且有收益的 Actor 组合。WM稳定编码/H8 Graph仍是显式基准试验，未在训练配置中悄悄启用；变慢或数值失败的候选默认关闭。

## 条件与证据

RTX4090，24564MiB，Isaac Lab2.3.1/PhysX，Torch2.7.0+cu128。真实环境4096、Replay容量512步/环境；Actor2048/H32，WM batch2048/H8/10次更新、3×2048，Critic305，FP32/TF32关闭。奖励、AMP、动作控制、原生事件及软存活保持原配置。

共同源checkpoint：V29从零预热500轮、联合训练30分钟的最终存档。每组内部固定权重、优化器状态、Replay起点/窗口、随机种子；一次冷诊断、一次更新预热及3次稳态样本。初始真实采集40向量步；分项测试不等同满Replay长训练。

独立服务器worktree `/root/reflex-v30-test`；输出 `/tmp/reflex_v30_gpu_20261107`。小型原始JSON及Profiler摘要已归档至 `benchmarks_v30_gpu_20261107/`，大型trace留服务器。原训练仓库、checkpoint和旧结果未覆盖。

## 一、已选用的 Actor 组合

来源：47c80b9，`actor_full_subsets_amp/actor_execution_v30.json`。

| 配置 | Actor秒/次 | Critic |
|---|---:|---|
| 原执行 | 2.5077 | 原配置 |
| FK复用＋计时器池更新精简 | 2.3435 | 原配置 |
| 再加全量事件子集直接执行 | 2.1167 | 原配置 |
| 再加AMP特征批处理 | **1.8709** | 原配置 |

- FK复用只在没有机器人根姿态/关节位置写入时生效；机器人速度变化仍正常更新。
- 计时器优化保留其他环境的时钟、触发及全部随机数调用。
- 全量事件子集优化：原生step的nonzero结果有序且唯一，长度等于批大小时可去掉恒等gather/child plan/index-copy；回调仍收到原来的None，部分子集保持原路径。
- AMP此前仅判别器批量化，本次将纯特征提取也移到H32轨迹之后，复用原时刻状态和FK；没有detach，没有重排任务历史或事件。

H32轨迹、事件、奖励、AMP、存活、截断对照通过；最大差约2.24e-8，来自Actor梯度。实际Actor/Critic Adam更新通过默认dtype容差。覆盖35次等待→发射、7次返回等待、687次截断。

## 二、最后一组：事件张量融合变慢，不选用

来源：cc86194，`actor_event_tensors/actor_execution_v30.json`。

| 指标 | 已验证组合 | 加纯事件张量/编解码融合 |
|---|---:|---:|
| Actor完整更新 | **1.7259秒** | 2.0837秒 |
| Critic更新 | 0.0469秒 | 0.0493秒 |
| 诊断前向中位 | 0.9483秒 | 1.2936秒 |
| 诊断BPTT中位 | 0.7680秒 | 0.8486秒 |
| Torch allocated峰值 | 15.57GiB | 16.29GiB |

Actor耗时增加 **20.7%**，显存增加约0.73GiB。诊断前反向与完整更新分开计时，不能相加替代完整更新。

正确性通过：本组所有轨迹输出、Actor梯度、Actor/Critic参数更新的最大差均为0；余弦约1。**正确不代表有性能收益，因此 `compile_event_tensors` 默认关闭，推荐配置不启用。** 暂不把变慢原因归结为未经分项证实的单个算子。

该试验在CPU阶段发现编译器可能消去图内mask clone，导致后续原生写入影响反向保存的mask；已将不可变mask快照留在编译边界外，CPU H32和GPU验证均通过。

## 三、WM稳定表达式与H8 Graph：通过，但仍是显式试验

来源：47c80b9，`wm_stable_graph/wm_rollout_v30.json`。

| 同一稳定编码下的执行 | WM10＋AMP秒/轮 | 数值检查 |
|---|---:|---|
| 原执行边界 | 0.5889 | 通过 |
| 单步损失融合 | 0.3498 | 通过 |
| H8递推＋损失融合 | 0.3094 | 通过 |
| H8＋CUDA Graph | **0.2456** | 通过，20次实际graph launch |

原编码下，单步/H8融合曾在首层权重第3列出现约2.5e-5～3.6e-5的更新差，超过默认容差；其余权重和最后一次梯度通过。该列为根姿态去yaw后的R[1,0]，对单位四元数理论上恒为0，浮点消去噪声被Adam放大。

`stable_canonical.py` 用精确零表达这一恒等式。FP64值及姿态切空间梯度测试证明该列为零；GPU稳定编码下原执行/单步/H8/Graph的损失、梯度和实际更新全部通过。没有降低网络精度或放宽容差。

这不是直接给旧模型静默换编码的理由。当前仅通过 `--wm_stable_heading_trial` 在基准模式临时替换，并在退出时恢复；普通训练入口拒绝该参数。主线训练配置仍沿用原编码。将该结果用于正式训练前，需要明确编码/normalizer和checkpoint迁移合同，并完成与Actor连续联跑。

## 五、原生事件一致性

64真实环境、24物理步的控制前缀覆盖悬停、发射、重投、机器人推力及扰动。验证后的组合和最后的张量试验均通过：

- 确定性应用计划与真实PhysX Post-control最大差0。
- 事件命令/控制状态误差最大约4.77e-7。
- 184次实际扰动写入，64条H32等待→发射轨迹。
- 发射速度对预测机器人位置的梯度范数约9.4586，有限且非零。
- 探针无优化器更新；未改变真实碰撞、奖励及reset规则。

## 六、第三方同机FP32受控对照

用户原报告约0.4006秒，BF16/TF32开启、Actor4096。本次保留原脚本，生成独立副本关闭BF16和TF32、Actor改2048，其他更新逻辑保留：

- WM10：262.5ms。
- Actor＋Critic：291.9ms；想象前向90.5ms、反向152.0ms。
- 合计 **554.4ms**，初始预热/编译145.4秒。

脚本实际执行backward和Adam，但使用合成动作/随机Replay、不启动Isaac，也没有Reflex箱子事件和对抗AMP，不能叫端到端训练吞吐。这个结果同时说明：精度差异和硬件不能解释Reflex剩余的全部性能差距。

## 合并边界与剩余工作

合并主线的是可复查代码、默认关闭的实验入口、CPU/GPU证据和已验证Actor配置。删除早期默认开启失败组合的V30配置，避免被误用。旧V23/V24/V29及原checkpoint保留。

尚缺：小于1秒的实际完整优化轮、WM稳定编码的正式迁移及连续联跑、新组合长期训练与真实效果评测。没有把独立最优值拼成已达标结果，也没有以缩短H32、改batch/奖励/事件或切断梯度换速度。

最终回归：CPU全量 **166 passed、1条既有TorchScript弃用警告**（469.41秒）；新增模块与测试Ruff通过，Git diff检查通过。完整CPU日志在 `benchmarks_v30_cpu_20261107/final_full_suite.txt`。
