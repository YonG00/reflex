# V37 GPU四组对照结果

## 结论

本轮研究完成，严格数值与实际单次Actor/Critic更新一致性通过，但没有可靠的完整更新提速。两个开关保持false，不启用到正式训练。GPU任务退出0，结束时92MiB/0%，原始JSON、日志及manifest已本地备份校验。

## 固定条件

新服务器30340，RTX4090 24GB，Torch2.7.0+cu128、Isaac Sim5.1、Isaac Lab2.3.1源码、NumPy1.26.4；checkpoint SHA256 f693022b0252e031caaf96bfa6ff282a4eda3294eea3ee67d468567e54ea293f。真实4096环境，采样40步后固定Replay；Actor2048/H32、FP32/TF32关闭、WM3×2048、原奖励/AMP/事件/解析软终止保持。只执行Actor+Critic实际更新，不含10次WM训练或在线真实采集吞吐。

每组预热2次，20轮交替配对；每次恢复同权重、Adam、RNG、Replay和调度器静态缓存，恢复开销不计入更新时间。源码hash在原始JSON中。起点SHA256 eb7a406b5e58f997c8cc86c3b9a245de04c3258c0a70cf78e32cbbe6260737a8。

## 正确性与覆盖

- 四组H32全部输出、原始Actor梯度最大差0，包括Physical、Post-control事件trace、观测、奖励、AMP、软终止、valid/truncated与launch模式。
- 四组实际Actor/Critic参数与梯度更新最大差0；恢复后WM未变、Actor恢复，样本SHA一致。
- 稳态unique_graphs/frames/graph_breaks新增均0，性能样本没有新增编译。
- 每组覆盖44次等待到发射、2次返回等待、501个截断条目；不是独立episode数，也不等于所有真实碰撞/重投子情形穷尽。
- 全部strict gate及performance_usable通过，不放宽容差。它是执行等价性检查，不是连续训练收敛或站立/接箱效果验证；没有正式训练和新ckpt。

## 冷启动与失败记录

新机没有旧Inductor缓存。r1在首轮reference反向编译达到600秒预算，退出124，GPU清理，未取得有效更新样本。r2复用缓存，reference首轮预热150.9517s、第二次1.7923s；分块预热1.7176/1.7378s，carry3.5916/1.7610s，组合1.7830/1.7110s。冷开销单列，未混入稳态；r1和r2分别存档，没有覆盖。没有定时faulthandler段错误。

## 对优化方向的影响

分块记录没有产生可用的完整更新收益；小范围carry融合也不足以改变约1.6秒瓶颈。代码上根部计划写入被局部化，但整个原生回调、事件视图准备/刷新、控制字段复制、奖励反向等仍执行；这些是后续候选，不是本轮新Profiler已证明的原因。本轮没有重新采集kernel/同步次数，不能虚构“减少了多少kernel”。

后续若继续，应先研究事件façade反复装配/刷新与字段复制的更大连续计算边界，复用已有V30 tensor_preparer和V33源码归因，避免重复开发已有功能；保持原回调、随机数顺序和梯度。不要将本轮未显著获益的候选启用到正式训练，也不要靠缩短H32或减少batch宣称达成1秒目标。
